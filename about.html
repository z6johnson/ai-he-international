NUD · About

Methodology and data status.

This dashboard supports a strategy engagement to launch a new AI-native university in the UAE ("NUD") with a top-200-in-20-years ranking ambition. It turns a curated source list on AI in global higher education into a working intelligence tool: a tracked watch list, a scan-style activity feed, and a prioritized reading brief. It is a static site — no server, no tracking, no external requests at runtime.

The three-layer model

Ongoing
Sources that compound: independent thinkers publishing continuously, and observatories tracking the field. These stay current in a way no report can.
Strategic core
Assessment, credentialing, and what a university is — the intellectual foundation for an institution planning witnessed human performance as its credential basis.
Founding
Building universities from scratch, the UAE regulatory machinery, Gulf strategy, and the rankings mechanics behind a top-200 ambition.

Tiers and provenance

Tier 1 / Tier 2
Tier 1 sources are primary — followed continuously and weighted first. Tier 2 are secondary or contextual.
Provenance: pdf
Item derives from the founding source document (the NUD engagement source list).
Provenance: websearch
Item found through targeted web research during a curation pass.
Provenance: scan
Item ingested automatically from a tracked RSS/Atom feed by the scan script.
UNTRIAGED
A scanned item no human has reviewed yet: its "why it matters" line is empty and its facets are inherited from its source. Triage means reading it, writing the why-line, correcting facets, and clearing the flag.

The staleness rule

Any report older than about twelve months is historical context, not current state. The footer's DATA STATUS line shows the baseline date — the last full human curation pass — and turns orange when it ages past 30 days. A stale baseline means the dashboard needs a scan and a triage pass, not that the sources are wrong.

How to run a scan

The scan script pulls tracked RSS/Atom feeds and appends new, deduplicated items to the data files. It is stdlib-only Python — no dependencies. From the repository root:

python3 scripts/scan.py --dry-run   # preview what would be added
python3 scripts/scan.py             # append new items + update meta
python3 scripts/scan.py --check     # lint data integrity

After a scan: open the Activity page, review items marked UNTRIAGED, fill in their why field in data/items.js, set needs_review to false, bump the baseline date in data/meta.js, and commit. Sources with no machine feed (most report publishers and observatories) are marked MANUAL on the Sources page — they are covered by periodic web-research passes, not the scan.

The scan also runs automatically every Monday via GitHub Actions (.github/workflows/scan.yml); when the repo is connected to Vercel, each ingest commit triggers a redeploy, so the feed refreshes itself. The scanner is deterministic RSS/Atom ingestion — no search agent, LLM, or API key involved. Only triage is a judgment step.
